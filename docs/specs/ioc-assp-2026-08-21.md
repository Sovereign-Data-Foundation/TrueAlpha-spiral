# ASSP Initial Operating Capability Deployment Target

## Milestone

August 21, 2026 is the target execution date for the Initial Operating Capability (IOC) deployment of the American Science and Security Platform (ASSP) within the TrueAlphaSpiral (TAS) architecture. The milestone establishes an operational checkpoint before the America 250 anniversary and focuses the implementation path on deterministic initialization, integer-only ledger semantics, and Chain of Mirrors validation readiness.

## Core Objectives

### Deterministic Cryptographic Initialization

- Finalize the `tas-sovereign-01` genesis payload as a deterministically reproducible cryptographic layout derived from the prime invariant lineage hash `A_0`.
- Restrict consensus key profiles to the Ed25519 signature scheme so validator identity, genesis signing, and consensus verification use one auditable signature surface.
- Reject overlapping consensus key schemes at IOC scope to reduce key-management ambiguity and implementation attack surface.

### utas Ledger and F1 Fee Distribution

- Encode all consensus-sensitive system parameters as integers in basis points, including the governance quorum value of `6667` basis points for 66.67% quorum.
- Forbid floating-point representation in ledger, governance, staking, and reward-distribution state transitions to prevent heterogeneous hardware from producing divergent consensus results.
- Operationalize passive, lazy-evaluation fee accounting with the F1 Fee Distribution model for validator staking, delegation, and reward distribution without O(N) block-write overhead.

### Chain of Mirrors Network and Inflection Point Mechanics

- Activate the Chain of Mirrors validation network for O(1) state verification of committed state roots and deterministic transition receipts.
- Enforce deterministic state transitions through mirror-consistent receipts rather than probabilistic output grading.
- Apply Inflection Point Mechanics to amplify invariant truth signals and reduce avoidable complexity without relying on external safety patches.

## IOC Acceptance Criteria

| Capability | Required IOC Condition |
| --- | --- |
| Genesis reproducibility | Independent builds produce the same `tas-sovereign-01` genesis payload from `A_0`. |
| Signature profile | Consensus keys validate only under Ed25519. |
| Parameter encoding | Consensus-sensitive ratios are represented as integer basis points. |
| Fee accounting | F1 rewards are lazily evaluated and do not require O(N) writes per block. |
| Mirror validation | Chain of Mirrors validators verify state transitions from deterministic receipts. |
| Complexity control | Inflection Point Mechanics reject non-deterministic or externally patched transition paths. |

## Operational Notes

The IOC scope favors a narrow deterministic surface over broad feature exposure. Any feature that requires floating-point consensus math, multiple signature families, probabilistic grading, or non-canonical serialization is deferred until it can be represented as a reproducible state transition with auditable receipts.
